# 2026-09-29

## What I did

- Get the HTTP response from the server and deserialize it into a C# data object.
- Handle server error responses to avoid deserializing invalid responses.
- Import the player package and related assets into the Unity project.
- Add `CommonIntent.cs` to store shared player intents that can later be provided by either a human player or an AI agent.
- Add `HumanIntent.cs` to read human player input and convert it into shared player intents.
- Route player input handling from `PlayerCrouch.cs` and `PlayerMovement.cs` to `HumanIntent.cs` to avoid hard-coding input handling in player-related scripts.
- Use action flags so multiple actions, such as sprinting and jumping, can be requested at the same time.

## What I learned

- How to organize dependencies between components so each script has a clearer responsibility.
- How separating input handling from gameplay logic makes the system easier to extend for different control sources such as human input and AI.
- How flag enums can store multiple actions at the same time.
- The difference between continuous actions, such as sprinting and crouching, and one-time actions, such as jumping.

## Problems

- I needed a way to share player actions without making gameplay scripts depend directly on keyboard input.
- Some player actions can happen at the same time, so using only one action value was not enough.
- One-time actions need to be cleared after they are handled, while continuous actions need to remain active while the input is held.
