# 2026-10-10

## What I did

- Connected the real `WorldObservation` snapshot to `ApiClients` and sent the active entity list to the FastAPI backend.
- Completed AI `MOVE` execution using backend target positions and added stopping/completion detection when the player reaches the target.
- Implemented `SessionManager` to coordinate the autonomous `Observe → Send → Act → Complete → Observe` loop.
- Added Play/Stop UI controls and synchronized the button/avatar animation with the actual session state.

## What I learned

- `WorldObservation` should be generated as a fresh snapshot before each backend request.
- An action being completed is different from the entire AI testing session being completed.
- `SessionManager` should only orchestrate the systems; observation, networking, and gameplay execution remain separate responsibilities.
- Async API requests must be awaited before the session continues to the next stage.
- Keeping `SessionManager` as the source of truth for `IsRunning` prevents the UI and AI session from becoming inconsistent.
- C# events can notify the UI when the session state changes instead of having the UI constantly check it.

## Problems

- Unity `JsonUtility` could not directly serialize the top-level `List<EntityObservation>`, so the observation list required a different JSON serialization approach.
- AI movement originally used the wrong Transform when calculating distance to the target.
- The same `ActionResponse` could continue being processed after an action finished, so completed responses needed to be consumed/cleared.
- The UI originally maintained its own running state, which could become different from the actual `SessionManager` state.
